# Skill

模型是工具，「Skill」是**怎么用**——一段可直接复制的提示词、一套固定步骤的工作流，或者一个能挂进 Agent 的技能。

和另外两个模块的分工：

- **资源库**：能白嫖的服务和平台
- **模型**：模型本身（上下文、额度、接口）
- **Skill**：把模型用出结果的**方法**，可以复制粘贴立刻跑

### 整篇论文结构化精读

**适用场景**：拿到一篇几十页的论文，想快速判断「值不值得细读」「能不能复现」，而不是逐段啃。

**需要什么**：上下文 ≥ 200K 的模型（能整篇塞进去，不用切片），例如 [智谱 GLM-4.7-Flash](/models/)。

**怎么用**：把下面整段贴给模型，然后把论文全文（或 PDF 转出的文字）接在后面。

```text
你是一位帮我把论文读薄的研究助理。下面是论文全文，请严格按以下结构输出：

1. 一句话结论（不超过 40 字，说清它做成了什么）
2. 研究问题与假设（作者想解决什么，预设了什么）
3. 数据与实验设置（数据来源、样本量、基线方法、评价指标）
4. 主要结果（带具体数字，标明是哪个数据集 / 哪张表）
5. 作者承认的局限（原文表述，不要替作者补充）
6. 我认为值得追的 3 个后续方向（每条给一句理由）

规则：
- 只用论文里的信息；任何推断都标注「推断」
- 论文未提及的，写「论文未提及」，不要猜
- 数字必须和原文一致，不要四舍五入到模糊表述
- 最后给一行「读完建议」：精读 / 只看方法 / 跳过，并说明依据

<在这里粘贴论文全文>
```

**产出**：一份六段式摘要，可以直接粘进文献笔记；末尾的「读完建议」用来决定下一步要不要投入时间。

**坑**：

- 200K 是上限，塞满会明显变慢；超过长度就按「方法 + 结果」两段分别喂，别硬塞
- 图表信息在纯文本里会丢，需要读图表时换视觉模型（如 `glm-4.6v-flash`），或把图单独截图提问
- 「推断」标注要盯着，模型很容易把推断写成事实

**验证日期**：2026-11-26

## 收录标准

1. **可直接跑**——复制粘贴就能用，不依赖只有作者才有的环境
2. **说清前提**——需要多长的上下文、需不需要视觉 / 联网、输入是什么格式
3. **写明产出**——跑完得到什么，能不能直接用
4. **写坑**——失败情况比成功案例更有价值
5. **不藏私**——完整提示词放正文，不放「关注后领取」
